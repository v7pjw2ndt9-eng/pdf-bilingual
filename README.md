# PDF 与网页双语阅读器

一个 Chrome 扩展，把 **PDF 和普通网页**都按段落翻译，译文插在原文下方。

针对的就是市面上 PDF 翻译"被按行打断"的毛病：pdf.js 抽出来的文本是碎的（一行常被切成十几段），
多数工具直接把一行当翻译单元，于是句子从中间断开、语义丢失。这里先把碎片重建成完整段落，
再整段送去翻译。

## 网页翻译

装好后在任意网页按 **Alt+T**（或点扩展图标 → 翻译此网页），译文会插在每个段落下方。
再按一次还原。可以给常读的站点勾「总是自动翻译此站点」。

网页这边的难点和 PDF 相反 —— 段落结构本来就在 DOM 里，问题是怎么**不把它切碎**、
也不把整块界面文字裹进来：

- **行内游程分组** —— 一个元素的子节点里，连续的文本和行内元素攒成一个单元，
  遇到块级子元素才断开。所以 `<p>前面<a>链接</a><em>强调</em>后面</p>` 始终是一整段，
  而 `<li>文字<ul>嵌套</ul></li>` 会得到「文字」和嵌套项各自独立的单元。
- **代码与公式占位符** —— 行内 `<code>`、KaTeX/MathJax 抽成 `⟦1⟧` 送去翻译，
  回来再换回原文。比只在提示词里叮嘱「别翻译代码」可靠得多；`<pre>` 代码块整体跳过。
- **界面外壳过滤** —— 导航、页脚、按钮里的短标签不翻。另有两条结构判据：
  「游程里没有裸文本、内容全在链接里、不超过两个词」和「纯锚点链接」，
  用来挡掉 Wikipedia 每个标题后面的 `[edit]`、`Skip to main content` 这类东西。
  这是结构判断，不是针对具体站点的硬编码。
- **已是中文的段落跳过** —— 中日韩字符占比超过 30% 就不翻，省 token。
- **懒加载** —— 只翻进入视口附近（800px 内）的段落。长文章不会一上来就把全文烧掉。
- **动态内容** —— MutationObserver 盯着 DOM，SPA 路由切换、无限滚动加载出来的
  新内容会自动接上。
- **单个 `<br>` 当空格，连续 `<br>` 当分段** —— 前者避免把软换行的长句切碎，
  后者避免老式 HTML（论坛正文）整页并成一个巨型单元。

API 调用放在 background service worker 里，不在页面上下文 —— Chrome 把 content script
的 fetch 纳入所在页面的 CORS 管辖，从页面直接打 `api.anthropic.com` 会被拦掉。
顺带好处是 API key 不进页面，各标签页共用同一个并发池和缓存。

## PDF 翻译做了什么

- **段落重建** —— 按栏分组基线聚合成行 → x 轴占用直方图找竖直白沟识别分栏 →
  识别跨栏元素定阅读顺序 → 用行距、行尾留白、首行缩进、字号跳变切段落。
  还处理了行末连字符（区分 `internation-alization` 的断词符和 `fine-tuning` 的复合词符）、
  悬挂缩进列表、页边距竖排水印、页眉页脚页码。
- **稿件行号** —— 投稿稿件和 bioRxiv/medRxiv 预印本每行都打行号。这些数字不摘掉，
  `23 enabled the generation of…` 会被当成编号小节标题，于是每行都被切成独立段落。
  按「纯数字 + 聚成窄带 + 落在正文块外的页边距 + 自上而下递增」四条同时满足才删，
  不会误伤表格里的数字列。预印本每页盖的版权水印横幅也会跳过，不浪费 token。
- **切片式排版** —— 把页面画布按段落边界切成横条，译文插在横条之间。原文版面保持不变，
  双栏论文左右两栏各自独立成流。
- **整批翻译** —— 一次请求送多个段落，模型能看到上下文，术语前后一致；比逐段请求快得多也便宜得多。
- **译文缓存** —— 按 `模型 + 目标语言 + 原文` 存 IndexedDB，重开同一篇不重复花钱。

## 装上

先拉 pdf.js（不入库，见下方「为什么 lib/ 不在仓库里」）：

```bash
./tools/fetch-pdfjs.sh
```

然后：

1. Chrome 打开 `chrome://extensions`
2. 右上角开「开发者模式」
3. 点「加载已解压的扩展程序」，选这个目录
4. 想读本地 PDF 的话，在扩展详情页把「允许访问文件网址」也打开

### 为什么 lib/ 不在仓库里

`lib/` 是 vendored 的 pdf.js，187 个文件约 4MB，其中 169 个是 CJK 字符映射表
（`.bcmap` 二进制）。这些文件锁定版本、从不改动，放进 git 只会让每次 diff 和
clone 都变重。`tools/fetch-pdfjs.sh` 按固定版本号从 npm 拉取，一条命令的事。
许可信息见 [THIRD-PARTY.md](THIRD-PARTY.md)。

装好后，网页上的 PDF 链接会自动用这个阅读器打开。也可以点扩展图标 →「打开本地 PDF」，
或者直接把 PDF 文件拖进阅读器窗口。

## 选后端

在扩展设置页（图标 → 设置）里选，三种：

### API（推荐，快）

填 API key 就能用。`Claude API` 和 `GPT API` 两套都支持，各填各的 key，随时切换。

- Claude：读论文用 `claude-sonnet-5`，图便宜用 `claude-haiku-4-5-20251001`
- GPT：Base URL 改成中转地址就能接 DeepSeek / Qwen / one-api 等任何 OpenAI 兼容服务
- 两边都有「拉取列表」按钮，直接从 API 拿当前可用的模型名，不用猜

一篇 20 页论文大约几毛到一块多，取决于模型。

### 本地桥接（用订阅额度，慢）

订阅账号（Claude Pro/Max、ChatGPT Plus）本身没有可供扩展调用的接口，但两家的官方 CLI
都支持订阅登录。桥接就是把 CLI 包成一个本地 HTTP 服务：

```bash
python3 bridge/bridge.py
```

只用 Python 标准库，不需要 pip 装东西，只监听 `127.0.0.1`。然后设置页选「本地桥接」。

前提是装好并登录过对应的 CLI：

```bash
curl -fsSL https://claude.ai/install.sh | bash    # Claude Code CLI，然后跑一次 claude 登录
brew install codex                                 # Codex CLI，然后 codex login 选 ChatGPT 账号
```

每段请求要起一次进程，比直连 API 慢很多（单次 3–8 秒），并发建议设 1–2。适合慢读。

### Google 免费端点

零配置零成本，质量一般，没 key 的时候兜底用。

## 排版模式

- **插入**（默认）—— 切开原文版面，译文紧跟在对应段落下方。最接近沉浸式翻译的体验。
- **分栏** —— 左边原页，右边译文列表。不动原版面。
- **悬停** —— 只显示原文，鼠标划过段落才弹出译文。最省 token。

## 设置里值得调的

- **术语表** —— 每行一条 `English=中文`，强制统一译法。读同一领域的论文很有用。
- **每次请求字数** —— 默认 3000。调大上下文更完整、术语更统一，但单次更慢。
- **跳过参考文献** —— 默认开，省掉一大堆没必要翻的条目。
- **并发请求** —— API 模式 3–6，桥接模式 1–2。

## 跑测试台

不用装扩展就能验证核心逻辑。样本 PDF 不入库（体积大 + 第三方版权），先取回来：

```bash
./tools/fetch-samples.sh
```

然后起个静态服务：

```bash
python3 -m http.server 8935 --directory .
```

- `http://localhost:8935/test/harness.html` —— 段落重建结果，含每页栏数、
  段落数、单行段落数、中位段落长度、残留行号数。
  **单行段落多、中位长度小 = 段落被按行切碎了。**
  样本覆盖 ACL 双栏、NIPS 单栏、带行号的 bioRxiv 稿件三种版式，
  末尾还有一个「合成行号注入」用例：往一页干净正文里插 24 个页边距行号，
  段落结构必须和注入前完全一致才算通过。
- `http://localhost:8935/test/viewer-test.html` —— 用假的 `chrome.*` 把真正的
  阅读器跑在普通网页里，检查切片几何、文字层对齐、译文插入。
  控制台里 `fakeTranslate()` 可以塞满假译文看版面撑不撑得住。
- `http://localhost:8935/test/webtest.html` —— 网页段落划分，34 条断言，
  样本里塞了行内标记、嵌套列表、行内代码、代码块、KaTeX、表格、
  已是中文的段落、隐藏元素、纯数字、`translate="no"`、导航/页脚短标签、
  单/双 `<br>`、锚点跳转链接。全绿才算过。
- 真实页面：`./tools/fetch-real-pages.sh` 抓 Wikipedia / arXiv / MDN 到
  `test/real/`（注入 `<base href>` 让原站 CSS 照常加载），打开后看 `window.PROBE`。
  Wikipedia 那篇一万多个节点，扫描应在 **40ms** 上下 —— 如果退化到几百毫秒，
  说明哪里又开始逐元素调 `getComputedStyle` 了。

## 已知限制

- 扫描件（图片型 PDF）没有文本层，抽不出文字，翻译不了。需要先 OCR。
- 旋转页（横向表格页）不做切片，自动退到分栏模式。
- 通栏图表如果没有通栏文字标题，在双栏页可能被从中间竖着切开。
- 行间公式会被跳过不翻译（本来也不该翻）；行内公式原样保留。
- 网页只翻主文档，`<iframe>` 里的内容不翻。
- 网页译文是纯文本，原文里的链接和加粗不会在译文里重现（原文就在上面一行）。
- Chrome 应用商店页、`chrome://` 开头的页面注入不了脚本，翻不了。
